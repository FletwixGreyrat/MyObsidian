
##### **1. SQL-инъекция**

Если на веб-сайте существует форма, через которую пользователь может отправить данные на сервер, и эти данные не проверяются должным образом, может быть проведена SQL-инъекция. Например, если пользователь вводит следующий запрос в поле поиска:

```sql
' OR '1'='1' --
```

Этот запрос может обойти аутентификацию или изменить данные в базе данных, если сервер уязвим.

- **Анализ**: На этапе анализа проверяются все формы ввода данных, поиск наличия SQL-инъекций. Если инъекции возможны, нужно протестировать, какие данные можно получить.

##### **2. XSS (межсайтовый скриптинг)**

XSS позволяет злоумышленнику внедрить вредоносный код в веб-страницу, который будет выполнен в браузере жертвы.

- **Анализ**: Проверяются все поля, которые могут быть использованы для отправки данных на сервер, на наличие внедрения JavaScript.

##### **3. Неправильная конфигурация SSL**

Например, если веб-сайт использует устаревший алгоритм шифрования (например, SSLv3), это может позволить злоумышленнику перехватить данные.

- **Анализ**: Проверка конфигураций SSL/TLS с помощью инструментов, таких как SSL Labs или testssl.sh.
