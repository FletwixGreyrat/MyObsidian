
### 1. **Сбор информации (Reconnaissance)**

	Этот этап заключается в получении всей возможной информации о цели, чтобы лучше понимать структуру веб-приложения и его уязвимые места. Этап делится на два типа: **активную** и **пассивную** разведку.

- **Пассивная разведка**: Получение информации без прямого взаимодействия с целью.
    - Использование **Whois** для сбора данных о домене.
    - Проверка публичных данных через **Google Dorking** (поиск уязвимостей через Google).
    - Анализ метаданных файлов (например, через **FOCA**).
- **Активная разведка**: Взаимодействие с целью для получения технических данных.
    - Использование инструмента **theHarvester** для сбора информации о поддоменах, email, IP-адресах.
    - Скрипты для поиска поддоменов (например, **Sublist3r**).


### **Цель этапа сбора информации:**

1. **Идентификация инфраструктуры**: Выяснить, какие технологии используются на сервере, какие порты и сервисы открыты, и как сервер взаимодействует с внешним миром.
2. **Нахождение уязвимостей для дальнейшего анализа**: Полученная информация будет использоваться на следующих этапах (сканирование и эксплуатация).
3. **Основы для социальной инженерии**: Собранная информация о сотрудниках, их должностях и контактных данных может быть использована для атак на человеческий фактор (фишинг, телефонные атаки).

Этот этап важен для формирования общей картины о системе и подготовки к следующему шагу — **анализу и сканированию**. Чем больше данных будет собрано на этапе разведки, тем выше шансы на успешное выявление уязвимостей на последующих этапах.
